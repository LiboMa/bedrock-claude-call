Amazon Bedrock Claude 示例 · 使用说明

本页说明如何安装、认证、运行本仓库的 Claude on Amazon Bedrock 示例脚本与测试入口。模型能力细节（thinking / effort / 采样 / 缓存矩阵）以仓库根目录 README.md 为准；内容依据 AWS 官方 Anthropic 模型卡总览（抓取快照 2026-10-14，事实清单见 .octopus/model-facts.md）。

标注 【待确认】 的内容表示模型卡未写明、本仓库无法核实；对应示例只演示一种写法并在失败时打印错误，不代表该写法已被官方确认。AWS 页面会持续更新，以官方页面为准。

前置条件：Python 3（建议使用虚拟环境）、可访问 Amazon Bedrock 的 AWS 账号，并在目标 Region 开通对应模型访问。

1. 安装依赖

python -m venv .venv && source .venv/bin/activate   # 可选
pip install -r requirements.txt   # boto3 + anthropic[bedrock] + aws-bedrock-token-generator
# 或 ./setup.sh（安装依赖并打印后续配置提示）
依赖最低版本用途
boto31.43.0bedrock-runtime 上的 Converse / InvokeModel
anthropic[bedrock]0.109.0Anthropic Messages API（runtime /anthropic 与 Mantle）
aws-bedrock-token-generator1.1.0从 AWS 凭证链生成短期 Bedrock API Key

2. 配置认证（二选一）

# 方式 A：Bedrock API Key（控制台 → API Keys → 创建长期 Key）
export AWS_BEARER_TOKEN_BEDROCK="<你的 Bedrock API Key>"

# 方式 B：标准 AWS 凭证链（~/.aws/credentials、AWS_PROFILE 等），无需额外配置
export AWS_REGION=us-east-1   # 示例默认使用 us-east-1

bedrock-runtime 上的 Messages API 示例（如 fable51_messages_runtime.py）用 aws_bedrock_token_generator.provide_token() 从凭证链生成短期 Key。

3. 数据保留模式一次性设置（按 Region）

模型需要的模式命令
Fable 5 / Fable 5.1aws_reviewaws bedrock put-account-data-retention --mode aws_review
Mythos 5 / Mythos 5.1provider_data_shareaws bedrock put-account-data-retention --mode provider_data_share

注意 Fable 5 需要的是 aws_review，不是 provider_data_share；provider_data_share 仅适用于 Mythos 5 / 5.1。Mythos 5.1 还需通过 Anthropic trusted access 获得访问资格（面向经审核的组织）。

4. 运行示例

  1. 每个示例都是独立脚本，直接运行即可，例如： 
    python claude55_family.py     # Haiku / Sonnet / Opus 5.5，Converse
python fable5_converse.py     # Fable 5 基础调用
python fable5_streaming.py    # Fable 5 流式
python opus48_all_apis.py     # Opus 4.8 四种 API 对照
  2. 受限或【待确认】的调用（Mythos、4.x thinking 写法、更早模型）失败时打印错误而不抛出，可据此判断是账号未开通还是参数问题。
  3. Fable / Mythos 系列可能返回 stop_reason: "refusal"（双用途分类器拦截），示例会按正常分支打印 stop_details。

最小可运行代码（Converse）

import boto3

client = boto3.client("bedrock-runtime", region_name="us-east-1")
response = client.converse(
    modelId="us.anthropic.claude-sonnet-5-5",
    messages=[{"role": "user", "content": [{"text": "介绍一下 Amazon Bedrock。"}]}],
    inferenceConfig={"maxTokens": 2048},
)
for block in response["output"]["message"]["content"]:
    if "text" in block:
        print(block["text"])

Mantle + Anthropic SDK（裸 ID）

from anthropic import AnthropicBedrockMantle

client = AnthropicBedrockMantle(aws_region="us-east-1")
message = client.messages.create(
    model="anthropic.claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Hello, Claude"}],
)
for block in message.content:
    if block.type == "text":
        print(block.text)

python test_all.py --syntax-only   # 仅语法检查 18 个示例脚本，不联网、不需要凭证
python test_all.py                 # 语法检查 + 27 项实测（覆盖全部 19 个模型，需 AWS 凭证与模型访问）

结果含义

常见报错

现象处理
ValidationException: ... model identifier is invalid检查 ID 代次：4.5 及更早要完整日期 + -v1:0；Opus 4.6 要 -v1；Opus 4.7+ 和 5 代用干净 ID。runtime 加推理档前缀；Mantle 用裸 ID。
thinking 参数被拒（400）Opus 4.7 / 4.8 仅支持 {"type": "adaptive"}；Opus 5.5、Fable / Mythos 5.x 不要传 disabled；其他 4.x 写法【待确认】，可先不传 thinking。
Opus 5 / Haiku 5.5 关闭 thinking 后 effort 报错关闭 thinking 时 effort 上限为 high。
Fable 5 / 5.1 报数据保留相关错误执行 aws bedrock put-account-data-retention --mode aws_review（每个 Region 一次）。
Mythos 5.1 用 Mantle 调不通Mythos 5.1 模型卡端点只列 bedrock-runtime，请用推理档 ID；Mythos 5 则只能走 Mantle 裸 ID。
返回 stop_reason: "refusal"双用途内容分类器拦截，按正常分支处理并查看 stop_details。
